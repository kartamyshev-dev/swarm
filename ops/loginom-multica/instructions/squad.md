Сквад «Обработчики узлов»: Генератор тасок → Тест-Манки #1 → Ловец Галюцинаций → Done согласованного этапа. Один проект и один сквад. Карточки назначаются вручную; дополнительного диспетчера нет. Генератор допускает один одновременный запуск, исполнитель и проверяющий — по восемь. Это лимиты запусков ролей, а не автоматическое назначение карточек. Native Codex runtime Multica уже изолирует настройки и историю задач с общей авторизацией Codex.

Один узел и согласованный этап — отдельная карточка с exact исходным SHA, веткой, целью PR, разрешёнными изменениями, защищёнными файлами, критериями и точкой продолжения. Ветка задания имеет приоритет над ref проекта. Stage 0 исследуется и принимается по исследовательским критериям; неначатые модельный и продуктовый пути обозначаются NOT_RUN. Успех исследования не подтверждает принятие полного обработчика.

Каждой карточке принадлежат собственные checkout, ветка, пара аккаунтов Loginom worker/reviewer, браузеры, CLI-состояние, пакеты и доказательства. Нельзя делить Loginom-аккаунт, чистить чужую сессию или сессию ещё работающей попытки. Повторы одного аккаунта сериализуются постоянной блокировкой, которую наследуют дочерние процессы. Каждая попытка создаёт отдельный каталог и профиль; старые попытки и неизвестные эффекты сохраняются для сверки.

Stage 0 использует существующий native вход Multica. Генератор создаёт Loginom-пару через provision-accounts.py --stage stage0; роли сохраняют stage=stage0, без OAuth и модельных настроек. Результат публикации содержит stage=stage0 и provider_model=NOT_RUN; секреты и вложения проверяются. accept-node.sh этот этап отклоняет. У владельца один ChatGPT-аккаунт: не требовать дополнительных входов и не активировать каталог восьми авторизаций.

Отдельно согласованная полная модельная приёмка Loginom CLI требует готового каталога восьми разных ChatGPT-аккаунтов. Решение для одного аккаунта согласуется отдельно; текущая обвязка клиент не меняет. Постоянные профили хранят только авторизацию вне рабочих каталогов и GC. В новый профиль попытки подключается только выбранный файл; обычное обновление токенов сохраняется в нём для следующего запуска. Обвязка удерживает блокировку до завершения и очистки журналов. Ожидание ограничено сроком и допускает отмену. Ошибка модели/квоты не переключает попытку на другой аккаунт. Повреждённая, отозванная или неопределённая OAuth-сессия исключается до восстановления владельцем; остальные работают.

Участники самостоятельно устраняют технические проблемы в назначенном объёме. Владельцу задают вопрос при изменении критериев или общего контракта, нехватке доступа либо трёх последовательных попытках без прогресса. Генератор использует настоящее упоминание [@Владелец](mention://member/@@OWNER@@). Blocked не заменяет доступное техническое восстановление. Общие изменения выполняются отдельной задачей; другие узлы продолжают работу. Зависимости требуют подтверждённой технической необходимости.

Передача роли допускается после завершения технических процессов, публикации чистого SHA и проверенных доказательств. Ловец независимо проверяет exact SHA и согласованный этап. DONE требует PASS именно этого этапа и receipt проверенных вложений. После Done/Cancelled карточки не возобновляются. GC касается рабочих каталогов, постоянные авторизации и аккаунты сохраняются. Merge и выпуск — отдельная команда владельца.
